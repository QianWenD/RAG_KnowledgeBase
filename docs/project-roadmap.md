# RAGPro 路线图和风险清单

更新时间：2026-05-22

这份文档把当前项目状态整理成几个执行方向。它不是死计划，后续每完成一批关键任务都应该更新。

## 当前状态

RAGPro 已经具备比较完整的本地产品面：

- API 和前端都由 FastAPI 提供。
- MySQL、Redis、Milvus、WSL Ubuntu、API 可以一起健康运行。
- 已有认证、知识源权限、组织和菜单管理、审计日志、会话、文档上传、批量上传、重建索引、统一问答。
- 已有 Python 单测、API 测试、Playwright E2E 测试和 RAG 评测数据。

现在的管理难点已经不是“做出一个东西”，而是“在不破坏现有可用能力的前提下，把它变成可维护、可上线的系统”。

## 方向一：可靠性基线

目标：启动、测试、本地运维变得稳定、重复、可交接。

近期任务：

- 增加一个发布检查命令或脚本，串起 Python、前端、评测检查。
- 统一测试文档，明确全量命令和几个常用定向命令。
- 增加轻量 CI，或者至少有本地 CI 替代流程。
- 管住 `tmp`、`runtime`、`test-results` 这类生成产物，避免干扰真实代码改动。

完成标准：

- 维护者能用一套明确命令验证项目。
- 生成文件要么被忽略，要么被明确标成运行状态。

## 方向二：安全和权限加固

目标：防止认证、知识源权限、上传、索引重建出现回归。

近期任务：

- 检查所有管理员接口，确认未登录和非管理员访问都会被拒绝。
- 补充单知识源、多知识源、无知识源用户的权限边界测试。
- 审查上传文件名、路径处理、批量上传临时目录清理。
- 上线前把生产敏感默认值改成环境变量配置说明。

完成标准：

- 认证和知识源权限有定向测试覆盖。
- 上传和重建索引的破坏性路径有明确测试和文档。

## 方向三：RAG 质量和评测

目标：让回答质量可度量，而不是靠感觉判断。

近期任务：

- 扩充 `packages/data/evaluation/current_domain_regression.json`，加入真实业务问题。
- 每次 RAG 改动都记录检索策略、引用来源、兜底情况和答案忠实度。
- 每个有效知识源至少有一个评测样例。
- 改路由或 Prompt 前，先记录当前已知坏例。

完成标准：

- RAG 改动可以用评测报告比较前后效果。
- 路由、检索、生成相关改动不能没有回归结果。

## 方向四：知识库运维体验

目标：让管理员能看懂上传、索引、诊断状态。

近期任务：

- 改善上传和重建索引的状态显示、失败恢复提示。
- 显示知识源级别的索引健康状态和最近任务记录。
- 给 `readiness: degraded` 和 `readiness: ok` 增加更直观的解释。
- 在没有明确迁移决策前，继续把 `apps/web` 作为当前产品前端。

完成标准：

- 管理员能判断某个知识源是否已上传、已索引、可查询、健康。
- 失败任务的信息足够维护者初步定位问题。

## 方向五：生产上线准备

目标：区分本地开发假设和生产运行假设。

近期任务：

- 明确上线目标：Windows 服务、Linux 单机、Docker Compose、云平台。
- 生产配置不使用本地默认账号密码。
- 补模型权重、Milvus、MySQL、Redis、Ollama 的部署说明。
- 明确上传文件、日志、索引、数据库、模型的备份策略。

完成标准：

- 运维人员能按文档准备生产依赖。
- 密钥、上传、索引、模型权重都有明确存储规则。

## 方向六：历史目录收口

目标：保留旧代码的参考价值，但不让它继续分叉成第二套产品。

近期任务：

- 明确 `packages/b_traditional_qa`、`packages/c_modular_rag`、`packages/d_multi_layer_rag` 是参考区。
- 梳理旧原型里还没迁移到 `src/ragpro` 的有价值能力。
- 删除或隔离无用生成文件前，先确认当前测试和文档没有依赖。

完成标准：

- 新功能只进正式主线。
- 旧目录是资料库，不是并行产品线。

## 近期执行顺序建议

1. 固化中文项目地图、文件整理清单、负责人手册。
2. 跑健康检查、Python 测试、前端 E2E。
3. 修复当前发布阻塞项。
4. 增加发布检查脚本或明确命令序列。
5. 补认证和知识源权限边界测试。
6. 扩充 RAG 评测集。
7. 确定生产部署形态。

## 风险清单

| 风险 | 等级 | 当前信号 | 缓解方式 |
| --- | --- | --- | --- |
| 运行数据被当成源码提交 | 高 | 存在 `runtime/uploads`、`tmp`、`test-results` | 严格 `.gitignore`，提交前看 `git status` |
| 开发默认凭证误用于生产 | 高 | 配置和文档中有本地默认值 | 生产只允许环境变量配置 |
| 知识源权限回归 | 高 | 多个接口依赖 source scope | 权限改动必须跑定向测试 |
| 重建索引误删数据 | 高 | reindex 会按 source 删除向量 | 保留路径白名单和删除边界测试 |
| RAG 质量凭感觉变化 | 中 | 评测存在但未自动化 | RAG 改动必须跑评测 |
| 旧原型继续承接新功能 | 中 | `packages/` 里有多套实现 | 明确主线，只在 `src/ragpro` 和 `apps/*` 开发 |
| 本地环境绑定机器 | 中 | 依赖 MySQL57、Redis、WSL、Milvus、Ollama | 明确生产部署目标和依赖准备 |
| 旧 Vue2 KBMS 依赖风险 | 中 | `packages/kbms-web` 是旧技术栈 | 仅作参考，除非明确迁移 |
