# 前端现状总结

更新时间：2026-04-24

## 一、当前前端总体情况

当前前端已经从“单页堆叠式控制台”逐步整理为“多页面后台工作台”结构，仍然保持原生 `HTML/CSS/JS + FastAPI 静态挂载` 方案，没有引入新的前端框架。

现阶段主要页面已经明确分工：

- `/`：总览页
- `/qa`：问答工作台
- `/knowledge`：知识运营主页
- `/knowledge/reindex`：索引重建页
- `/knowledge/sources`：来源管理页
- `/users`：用户管理总览页
- `/users/access`：角色与授权页
- `/users/security`：安全操作页
- `/users/audit`：审计日志页
- `/login`：登录页
- `/register`：注册页

当前前端已经形成统一后台壳层：

- 左侧统一导航
- 顶部状态区与页面标题区
- 公共会话/身份区
- 公共样式文件 `apps/web/styles.css`
- 公共行为文件 `apps/web/common.js`

## 二、这一轮前端已经完成的重点变化

### 1. 页面结构层面

已经完成从“功能混堆”向“页面拆分”的整理，问答、知识运营、权限管理不再继续挤在同一个页面里。

权限管理已拆为四个独立页面：

- 用户总览：`/users`
- 角色与授权：`/users/access`
- 安全操作：`/users/security`
- 审计日志：`/users/audit`

### 2. 视觉与布局层面

目前整体风格已经偏向“企业后台控制台”而不是“原型页”：

- 页面模块边界更清楚
- 顶部与左侧导航更统一
- 表格、筛选区、操作区样式趋于一致
- 权限页内部的间距、按钮、操作入口已经做过多轮整理

### 3. 用户管理模块层面

用户管理是这一轮改动最多、也最细的模块，目前已经完成：

- 用户信息区从内嵌展开改为弹框创建
- “新增”按钮可打开新增用户弹框
- “刷新”按钮已恢复有效，具备忙碌态和成功提示
- 创建账号时有弹框内反馈，不再只在页面顶部提示
- 创建失败时可在弹框内直接显示错误原因
- 常见英文错误已转换为中文提示
- 初始密码过短时，不再弹浏览器英文校验，而是显示中文提示

当前新增用户弹框的交互状态是：

- 可打开
- 可关闭
- 支持取消
- 支持点击遮罩关闭
- 支持 `Esc` 关闭
- 提交时有进行中提示
- 校验失败时在弹框内直接显示中文错误

### 4. 审计日志层面

审计日志页已经具备时间范围筛选能力，并且已有快捷时间范围交互。

### 5. 测试与验证层面

前端验证已经不再只靠手工点页面，当前有两类验证：

- Mock 前端 Playwright smoke：`npm run test:e2e`
- 可选真实权限链路 E2E：`npm run test:e2e:live`

截至本次总结前，最近一次前端 smoke 结果为：

- `npm run test:e2e`
- 13 条通过

## 三、当前前端的技术组织方式

当前前端主要按下面的结构组织：

- 页面结构：各页面自己的 `html`
- 页面行为：各页面自己的 `js`
- 公共行为：`apps/web/common.js`
- 公共样式：`apps/web/styles.css`

目前对应关系比较清晰：

- `index.html` + `dashboard.js`
- `qa.html` + `qa.js`
- `knowledge.html` + `knowledge.js`
- `knowledge_reindex.html` + `knowledge_reindex.js`
- `knowledge_sources.html` + `knowledge_sources.js`
- `users.html` + `users.js`
- `users_access.html` + `users_access.js`
- `users_security.html` + `users_security.js`
- `users_audit.html` + `users_audit.js`

公共层承担的职责已经比较明确：

- 登录态与身份刷新
- 公共状态提示
- API 请求与错误包装
- 权限页公共创建用户辅助逻辑
- 公共来源选择与来源校验逻辑

## 四、当前前端已经具备的统一能力

从“页面能力”角度看，目前前端已经具备：

- 登录与注册页面
- 登录态识别
- 用户身份信息展示
- 问答工作台交互
- 知识上传与来源管理交互
- 权限页拆分导航
- 用户创建、授权、安全操作、审计查看
- 统一错误提示与部分中文化提示
- 基础 E2E 回归能力

从“后台壳层”角度看，目前已经具备：

- 统一导航框架
- 页面级状态提示
- 表单、表格、弹框、按钮的一套共用风格基础

## 五、当前仍然存在的前端问题

虽然这一轮已经把页面从“能用”推进到了“比较像后台”，但如果要继续往“成熟企业系统”靠，当前还有几类问题仍然明显存在：

### 1. 页面之间成熟度不完全一致

现在最细化的页面是权限模块，尤其是 `/users`、`/users/access`、`/users/security`、`/users/audit`。  
但总览页、问答页、知识运营页虽然已经重构过，页面成熟度和细节一致性还没有完全拉平。

### 2. 不同模块的“后台感”强弱不一致

有些页面已经比较像正式系统页面，有些页面仍然更像“重构后的工具页”，主要差异体现在：

- 模块密度控制
- 说明文案取舍
- 表格区和操作区的层级关系
- 信息卡片与业务卡片的统一性

### 3. 组件层级还可以继续收敛

当前虽然已有统一样式，但距离“形成一套非常稳定的设计规范”还有差距，主要体现在：

- 弹框、筛选区、工具栏、分页区还可继续标准化
- 各页标题区、状态区的表现还可以进一步统一
- 表单项的标签布局和反馈方式仍可继续收口

### 4. 与成熟业务系统相比，还缺少“对标式打磨”

当前更像是“按内部逻辑重构好了”，但还没有系统性对比某个成熟开发系统、运维系统、权限后台系统，再逐项做视觉与结构对齐。

这也是下一阶段最适合做的事情。

## 六、如果下一轮要拿其他开发系统页面做对比，建议对比什么

下一轮如果要重新根据其他开发系统页面作对比并改造，建议不要零散比，而是按下面几个维度去比：

### 1. 后台框架层

重点比较：

- 顶栏高度与信息密度
- 左侧导航的层级感
- 页面标题区的组织方式
- 子导航是否够清楚

### 2. 筛选与工具栏层

重点比较：

- 筛选区是否像正式台账页
- 筛选条件的排列方式
- 查询、重置、新增、刷新等按钮的位置关系
- 工具栏是否足够简洁

### 3. 表格与列表层

重点比较：

- 列宽控制
- 行高与字距
- 操作列密度
- 分页器样式
- 空状态和失败状态表现

### 4. 弹框与表单层

重点比较：

- 弹框尺寸
- 标题、副标题、关闭按钮布局
- 表单标签与输入框的上下关系
- 校验提示的位置与风格
- 主按钮与次按钮的权重

### 5. 业务语义层

重点比较：

- 模块是否过多
- 文案是否过重
- 页面是否保留了真正核心动作
- 同一页面是否承担了过多解释功能

## 七、下一轮前端对比改造时，建议的优先顺序

如果下一轮开始做“对标其他系统页面”的改造，建议优先顺序如下：

1. 先统一后台壳层：顶栏、左栏、页面标题区、工具栏
2. 再统一权限模块：`/users`、`/users/access`、`/users/security`、`/users/audit`
3. 再统一知识运营模块：`/knowledge`、`/knowledge/sources`、`/knowledge/reindex`
4. 最后再统一总览与问答页的视觉语言

原因很简单：

- 权限页现在最成熟，适合作为样板
- 知识运营页是第二优先级，业务最重
- 总览和问答页更偏体验展示，适合最后统一

## 八、当前可直接作为“对标改造基线”的页面

如果要从当前页面里选一个“先作为样板继续打磨”的模块，建议优先选：

- `/users`
- `/users/access`
- `/users/security`
- `/users/audit`

理由：

- 当前改动最多
- 结构已经较稳定
- 有真实权限业务支撑
- 表格、筛选、弹框、状态提示、审计能力都在这里

## 九、本次总结结论

截至 2026-04-24，前端已经不再是原型式拼接页面，已经进入“多页面后台工作台 + 权限治理台账化”的阶段。

当前最成熟的模块是权限与用户管理模块。  
当前最适合继续做的，不是再零散修小点，而是拿一个成熟开发系统或业务后台系统作为对比对象，按：

- 后台壳层
- 筛选工具栏
- 表格台账
- 弹框表单
- 业务信息密度

这五个维度，重新系统性收一轮页面风格。

本次文档只做现状总结与汇总，不启动新的页面改造。
